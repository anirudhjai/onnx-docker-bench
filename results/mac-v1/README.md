# Mac v1 results

The v1 study's data: ONNX Runtime 1.31.0, ResNet-50 (fp32 and int8 dynamic-quantized),
224×224, batch 1, in Docker containers limited with `--cpus` on an M1 MacBook Pro.
Figures and the summary table are generated from these files by `scripts/analyze.py`.

| File | What |
|---|---|
| `pilot.csv`, `pilot.log`, `raw/` (pilot run ids) | Stage 0: each of the 22 cells once at 100 iterations (`matrices/mac-v1-pilot.json`). Only used to set iteration caps and ETAs. |
| `results.csv`, `results.log`, `console-main.log`, `raw/` | The official run (`matrices/mac-v1.json`): 22 cells × 4 repeats, one row per container run. `raw/<run_id>.csv` holds every timed iteration. |
| `machine-pilot-local.json`, `machine-main-local.json` | Machine and software record at the start of each stage (`scripts/record_machine.py`). |
| `run-start.txt` | Conditions captured immediately before the official run started. |

Summary table, checks and figures: `docs/results_summary.md`, `docs/figures/`
(generated by `scripts/analyze.py`).

## Conditions (stated, not controlled away)

- **Hardware:** MacBook Pro 13" M1 (MacBookPro17,1), 4 performance + 4 efficiency
  cores, 8 GB, macOS 26.5.1. The Docker VM's vCPUs are scheduled by macOS across
  both core types.
- **Docker:** Docker Desktop 29.6.1, VM with 8 vCPUs and 3.8 GiB, kernel
  6.12.76-linuxkit, cgroup v2 (cgroupfs driver). Containers see all 8 vCPUs.
  `--cpus` sets a CFS quota (100 ms period).
- **Rosetta setting off.** "Use Rosetta for x86_64/amd64 emulation on Apple
  Silicon" was disabled, and no Rosetta binfmt handler was registered in the VM
  (checked at run start; x86_64 is handled by QEMU). With it on, this M1 ran ORT
  ~6.6x slower in containers; see `investigations/rosetta-tso/`.
- **Battery, then AC.** The official run started on battery by decision (90%, Low
  Power Mode off). The Mac was plugged in during the first repeat round: the first
  16 runs (all round 1) ran on battery (90→83%), the remaining 72 on AC (first AC
  run 2026-10-14T23:21Z). The pilot ran on AC. Every row records `power_source` and
  `battery_pct` at the start of that run. Power is therefore confounded with run
  order (battery = early round 1). In 12 of the 16 cells that have a battery run, it
  is within 2% of the median of the same cell's AC runs; the other 4 are
  oversubscribed default-thread cells whose AC runs also vary widely, and the
  battery run is slower in 3 and faster in 1. No consistent power effect is visible
  (`docs/results_summary.md`, Checks).
- **Sleep prevented:** the runner was wrapped in `caffeinate -dimsu`.
- **Idle-ish, not idle.** At start the Mac was ~85% idle; the macOS window server (~25%
  of one core), other desktop apps (~25%) and Docker Desktop (~7%) were the main
  users. Heavy apps were closed and the Mac was not used heavily during the run.
  `run-start.txt` keeps only the idle percentage and load average. macOS load averages count differently from Linux and are not
  comparable with the per-row `loadavg_1m`, which is the Docker VM's.

## Statistics

From `docs/EXPERIMENT_PLAN.md`, with two v1 deviations decided before the run to fit
~3 h (the plan's statistics would have taken 4 h 25 m on this machine):

- **4 repeats per cell instead of 5**, interleaved: each repeat runs all 22 cells in
  a fresh seeded random order (seed 20261018).
- **Iteration cap of 300 s of timed loop per run instead of 600 s** (target 1000 timed
  iterations, floor 300, 50 warmup). This only affects the three slowest cells,
  all at `--cpus=1` with ORT's default threads: fp32 spin on, int8 spin on, and fp32
  spin off. Those are 4–11x slower than matched threads, so a coarser p99 there
  can't change any conclusion, and the time saved buys a 4th repeat for every cell.
  The caps come from the pilot's latencies, so all repeats of a cell use the same
  iteration count (`iters` column).

## Reproduce

```bash
python3 scripts/run_matrix.py matrices/mac-v1-pilot.json --build
python3 scripts/record_machine.py --stage main --out-dir results/mac-v1
caffeinate -dimsu python3 scripts/run_matrix.py matrices/mac-v1.json --estimates results/mac-v1/pilot.csv
.venv/bin/python scripts/analyze.py
```
